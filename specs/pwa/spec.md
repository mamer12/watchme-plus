# PWA

## Purpose

Installable, fast to start and usable offline for everything except video. Config: `pwa.config.ts` (vite-plugin-pwa,
generateSW), icons in `public/` (generated by `scripts/gen-icons.py`), `index.html`.

## Requirements

### PWA-001: Manifest and icons
The system SHALL ship a manifest with name and short_name "Watchme+", standalone display, start URL `/`, dark theme and
background (#141414), and 192/512 PNG icons plus a 512 maskable icon of the red "W+" mark (no third-party brand
assets).

- Verification: test

#### Scenario: Install on Android
- GIVEN Chrome on Android
- WHEN the user installs the app
- THEN it launches standalone as "Watchme+" with the W+ icon

### PWA-002: Caching strategy
The service worker SHALL precache the app shell, serve navigations from `index.html` (except `/api/*`), cache the catalog
API answers network-first (8 s timeout), the TMDB proxy stale-while-revalidate, and images (the catalog, TMDB, YouTube
thumbnails) cache-first with expiry; it SHALL NOT cache video files or subtitles.

- Verification: test

#### Scenario: Video request
- GIVEN a request to `cdn.shabakaty.com/...mp4`
- WHEN the service worker sees it
- THEN no cache route handles it

### PWA-003: Offline
The system SHALL keep working offline from the cached shell and last-good data (API-009), show an offline banner, and
explain that videos need a connection.

- Verification: manual — load Home, go offline (DevTools), reload: Home renders from cache with the offline banner;
  My List and Settings work.

#### Scenario: Offline reload
- GIVEN a previous visit
- WHEN the page reloads offline
- THEN rows render from cached data

### PWA-004: iOS
The system SHALL include `apple-touch-icon`, `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`
(black-translucent), `apple-mobile-web-app-title` and `theme-color`, and respect safe-area insets.

- Verification: test

#### Scenario: Add to Home Screen
- GIVEN Safari on iPhone
- WHEN added to the home screen
- THEN it opens full screen with the W+ icon and a translucent status bar

### PWA-005: Updates
The system SHALL update the service worker automatically (`registerType: autoUpdate`, `skipWaiting`, `clientsClaim`),
reload the page once when a new worker takes over a page an older one controlled (never on the first install; at most
once per 60 s, guarded by a sessionStorage timestamp), and never cache `sw.js`, `pf-sw.js`, `index.html` or `/` at the
edge (`Cache-Control: public, max-age=0, must-revalidate` in `vercel.json`).

- Verification: test

#### Scenario: New deploy
- GIVEN a new deployment and an old worker controlling the page
- WHEN the user opens the site
- THEN the new worker takes over and the page reloads once into the new version

#### Scenario: No loop
- GIVEN the page already reloaded for an update less than 60 s ago
- WHEN another controller change happens
- THEN it does not reload again

### PWA-006: Reset by address
The system SHALL, when the address has `?reset=1` (also `?reset`, `?reset=true`) or `#reset`, run the "Reset this site"
steps (SET-009) immediately without asking, then replace the address with `/`, and SHALL offer a "Reset site data" link
in the first onboarding step and next to the catalog-unreachable banner, opening the same confirmation dialog.

- Verification: test
- Depends on: SET-009

#### Scenario: Stuck on an old build
- GIVEN an old build is shown that has no reset button
- WHEN the person opens `/?reset=1`
- THEN the site data and service worker are removed and the home page loads fresh

### PERF-007: Image cache
The service worker SHALL cache images from both catalog image hosts cache-first, up to 300 entries for 30 days, for
responses with status 0 or 200, so repeat views are instant.

- Verification: test
- Depends on: PWA-002

#### Scenario: Repeat view
- GIVEN a poster was shown before
- WHEN Home opens again
- THEN it comes from the cache

### PERF-008: Connection hints
The system SHALL preconnect only to the active provider's hosts (catalog, images, video CDN, and the signed file host
once known), with `dns-prefetch` for the other provider in the built page.

- Verification: test
- Depends on: `src/lib/hints.ts`, `vite.config.ts`

#### Scenario: Other
- GIVEN the provider is Other
- WHEN the app starts
- THEN it preconnects to the mirror's hosts and not to the other provider's
